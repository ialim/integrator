- (decision) [ADOPTED] Paradigm: modular monolith. Modules: Identity&Access, Catalogue&Stock, Pricing, Projects, Orders&Payments, CreditNotes, Fulfilment, Documentation, Notifications, Returns, Staff&Audit. Each module owns its tables; all state changes only via that module's Action classes (transaction + lock/idempotency + transition guard + audit). API controllers, Filament, jobs are thin callers. Prevents duplicated money logic across entry points.
- (decision) [ADOPTED] Strict boundaries: cross-module access only through the other module's public Actions and Query classes, never its Eloquent models or tables. Prevents hidden coupling and second writers.
- (decision) [ADOPTED] Filament: each module ships its own Filament resources over its own models; cross-module fields via the other module's Query classes/read models/views; every Filament button calls an Action; Filament's built-in model save never touches money or state fields. Prevents Filament becoming a second writer.
- (decision) [ADOPTED] Reporting module: read-only, may read any module's tables directly, never writes; the only exception to strict boundaries.
- (decision) [ADOPTED] PostgreSQL as the single database (numeric, FOR UPDATE SKIP LOCKED for queues, partial unique indexes for one-live/one-active invariants, jsonb price snapshots).
- (decision) [ADOPTED] Money: never float in PHP or JS. DB numeric fixed scale (USD 4dp, NGN 2dp); one Money value type in PHP; money serialized as decimal strings in JSON; the PWA never computes a persisted price, only displays server figures and as-of totals.
